# 配布版の確認範囲

Windows／Unity 6000.3.23f1 Editor Playで検証。ユーザー指定により15分の実時間運転は省略し、65秒以上を基準としました。

LightShaft＋移動カメラ＋Unity AudioSourceの計算生成音声を使用。録画範囲はGame View全体です。

## 最終コードでの実測（2026-09-24）

| 項目 | 1080p試験 | 循環・Pause試験 |
|---|---:|---:|
| 保存解像度 / fps | 1920×1080 / 60 | 640×360 / 30 |
| 取得元Game View | 3840×2160全域 | 3840×2160全域 |
| 保持時間設定 | 900秒 | 5秒 |
| 実運転 | 65秒以上 | 約12秒＋Pause約1秒 |
| 保存MP4映像 | 3,901枚 / 65.0167秒 | 93枚 / 3.1秒 |
| 保存MP4音声 | 65.024秒 | 3.11467秒 |
| 重複補完 / スキップ | 13 / 0 | 1 / 0 |
| 古い区間の削除 | 0区間 | 5区間 |
| 音声欠落ブロック | 0 | 0 |
| 開始時の音声不足（無音補完） | 2,048サンプルフレーム（約43ms） | 0 |

カウンターは保存中も進むため、録画全体の値と保存MP4のフレーム数は一致しません。全映像・音声をWindows Media Foundationで復号し、タイムスタンプの単調増加、四隅の色マーカー、上下方向、画面全域、音声RMSと区間接続を確認しました。連続テスト音の内部無音連続長は1080pで4サンプル値、640pで2サンプル値です。

GPU NV12変換を使用。正常停止後のセッションキャッシュ削除も確認しました。平均ゲームフレーム時間は、録画前3秒で14.14ms、1080p録画中で14.32msでした。移動シーン・短時間の比較であり、厳密な負荷差や他のPCの性能を保証する測定ではありません。

保存キーは新Input SystemへF9状態を注入し、Recorder.Updateから実保存まで確認しています。物理キーボードの手操作を検証したものではありません。InspectorとAPIからの保存も利用できます。

## 確認範囲と残る制限

- ユーザー指定により15分の実時間運転は行っていません。保持上限900秒の設定で65秒以上を実測しました。
- 60 fpsは出力ファイルの時間軸です。毎秒60枚の異なる画面を保証せず、描画不足時は直前フレームで補完します。
- LightShaftプロジェクトのEditor終了時にJobTempAlloc警告が出ています。録画追加前にも確認されていた警告で、原因は特定していません。
- ゲームのPlayerビルドは対象外です。ハードウェアエンコーダーの実使用、他のGPU／Windows構成は未確認です。
- 独立プロジェクトへのパッケージ導入結果は、配布パッケージと同じフォルダーの検証レポートに記録します。

検証スクリプト：`Tools/ReplayCapture/check_native.py`、`verify_disk_editor.py`。実行記録：`Artifacts/ReplayCapture/DiskEditorCheck/verification.txt`。これらの検証用スクリプト・LightShaftシーンはunitypackageに含めません。
