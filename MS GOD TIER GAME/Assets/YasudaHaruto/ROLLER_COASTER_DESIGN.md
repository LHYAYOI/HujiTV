## 現行の再利用可否
| 要件 | 現行 | 判断 |
| --- | --- | --- |
| 走行経路編集・走行開始 | Arai/Script/Trokko/SplineController2、StageSpline、CartController | 基盤を流用候補とする。Containerの先頭スプラインを使用 |

| 物の生成 | GimmickSplineCreateObject | Prefab生成と時間後破棄を流用候補とする。生成した車両への走行経路・開始位置の注入はない |
| 対向車両 | CartController / WatanabeKaitoのSplineMoveEnemy | 走行計算の参考になるが、対向車両専用演出は未発見。Enemy側は敵データへの依存があり、そのまま単体車両へ使う前提にしない |

## 推奨構成
1. ルートの正本は既存SplineContainerとする。初期は既存制約に合わせて1 Containerにつき走行用Splineは1本。生成専用の別線を手作業で同期しない。
2. 編集用の生成コンポーネントを担当領域へ追加する案。参照Spline、生成区間、素材Prefab/Mesh、長手軸、素材1個の長さ、横/高さオフセット、分割密度、配置間隔、ロール追従を設定する。
3. 生成方式を素材ごとに選ぶ。レール本体・壁・床は頂点を経路に沿って曲げる。枕木・支柱・照明・岩などは形を保って反復配置する。遠景は手置きも許容する。
4. 各生成レイヤーに開始/終了区間を設け、レールなし、壁だけ、床なし等を表す。走行経路は残せるため「レールが切れた先の演出」も作れる。ただし自由落下の物理とは別仕様。
5. 編集中のプレビューと明示的な再生成、Undoに対応する。生成物は専用の子階層に限定し、手置きオブジェクトや素材原本を上書きしない。完成後は生成済みメッシュを保存して再生時の毎フレーム再生成を避ける。
6. ギミックは既存ルート配下の配置を活用。対向車両は出現地点・対向用ルート・開始位置・速度・終了条件を持つ追加演出を候補とする。車両ごとにイベント対象を識別し、対向車がプレイヤー用停止/分岐を発火しない設計にする。

## 標準機能で足りる範囲
- SplineInstantiateはPrefabを沿わせて配置する機能。素材自体を曲げないため、短い枕木・支柱・装飾に適する。長い直線レールを並べるだけでは急カーブの隙間や重なりは解消しない。
- SplineExtrudeは断面を押し出す方式。単純なレールや仮トンネルには候補だが、既存の完成したFBXをその形・装飾のまま曲げる機能とは異なる。
- 希望する「手持ちのレール素材を滑らかにつなぐ」はメッシュ変形方式を中心に設計する。素材が低分割なら事前の細分化または生成側の分割処理が必要。

## 先に整理する整合性
- 現行CartControllerとGimmickSplineは距離相当値/全長をそのままSpline評価値にする。曲線上の実距離での等速移動ではなく、生成側だけ実距離方式にすると地点指定が一致しない。
- 生成側内部の実距離配置と既存イベント指定値を明確に区別する。初期に互換変換を用意するか、担当者への相談後に走行・イベントを一括して実距離へ揃えるか判断する。既存値の無断解釈変更はしない。
- CartControllerは位置に即追従し回転はLerpで遅れる。急降下・急カーブ・ロールで車体とレールが合うかを確認する。接線とupを生成・車体・カメラで共有し、鉛直区間の反転を避ける。
- 現行イベント入口はCartHitter.OnCollisionEnter。高速走行での通過漏れ、交差するルート間の誤発火、同じ場所の再通過、Range中の別ルート切替を検証対象とする。高速演出は進捗の前フレーム→現フレーム間の通過判定を追加する案。
- RangeはPair必須であり、同地点ペアでは進捗除算の問題がある。未設定・同地点・逆行・ループ越境の扱いを決める。
- モデルの端点断面・幅・軸・原点を合わせ、法線/接線、UV、複数マテリアルを維持する。Colliderは表示メッシュと別の簡易形状を基本候補とする。

## 素材と演出の未確定事項
- レールと背景の対象FBX/Prefabを名前検索では特定できなかった。大きなFBX内のサブメッシュの可能性もあり、素材が存在しないとは判断しない。対象パスを確認してから長さ・継ぎ目・頂点密度・Read/Write・Colliderを調査する。
- 背景がトンネルの壁/天井/床なのか、外の景観なのかで生成対象を分ける。
- 対向車は脅かすだけか、接触すると失敗か。プレイヤーが操作して回避するか、既定ルートで直前に曲がる演出か。
- 線路切れの落下は軌道に沿う演出か、自由落下か。初期案は姿勢とカメラを調整しやすい専用Spline区間とする。

## 実装承認後の確認順
素材1つの継ぎ目と曲げ品質 → ユーザー編集への再生成 → 同じ線上の走行と姿勢 → 加減速と高速イベント → 揺れ接続 → 対向車と回避/落下。
変更候補は担当領域の新規生成機能と専用の確認用構成。Arai/Hamadaのコード、共有Scene/Prefab、Import設定等を変更する場合は、対象と変更内容を提示して事前相談する。

## 使用素材の特定と設計の具体化（2026-11-12追記）
- ユーザー指定でAssets/map/bunki/duct_lane.fbxを確認。前節の「素材未特定」は解消。背景はこのFBX内の直線囲いを使う予定。
- FBXバイナリを読み取り専用で解析し、GeometryとModelの接続を確認。rail_straight（40コントロールポイント、30ポリゴン）、duct_straight（8コントロールポイント、4ポリゴン）が対象。ほかにduct_slope / duct_corner / rail_cornerが含まれる。数はUnityインポート後の分割済み頂点数ではない。

- rail_straightのGeometry寸法はX約252.6872、Y約22.0444、Z約303.3808（FBX座標）。形状幅があるため、実際のレール方向と接続断面の視覚確認は必要。Xは6水準、Zは8水準で、細かく分割された連続曲面ではない。
- 両Modelは素材展示のためと思われる別々の位置に置かれている。生成時はFBX全体を並べず、対象の子メッシュを個別に取り出す。配置用Translationを継承せず、形状に必要なScaleは反映し、始端/終端と進行軸を正規化した生成用データを担当フォルダに作る案。原本は維持する。
- 囲いは4ポリゴンで、端の開いた筒状構成と整合する。ただし面の向き・内側からの表示・継ぎ目はUnityで未確認。
- 今回の素材では「既存頂点の座標を曲げるだけ」は不十分。長手方向の一定間隔で面を分割し、UV/法線/マテリアルを維持してから曲げる。分割面の境界は隣接面と揃えて隙間を防ぐ。急カーブでは内側の潰れと囲いの自己交差を確認する。
- rail_straightとduct_straightは別レイヤーで、同じSplineを参照。端点を指定し、レール基準の横幅/高さと囲い中心からの相対位置を設定する。囲いだけ/レールだけの区間も指定可能にする。
- .metaはisReadable=0、addColliders=0。実行時に直接Mesh.verticesを読む前提は置かず、Editorで取り出して分割した生成用Meshを保存する方式を優先検討。Importer設定の変更が必要なら事前相談する。
