# ルーン画像取り込み・設定ページ・お邪魔要素の設計案

2026-10-27。静的調査に基づく案。ゲームコード・Scene・Prefabへの実装は未実施。ユーザー提示の解除操作は要件として記録し、数値や未決定の挙動は確定扱いにしない。

## 現状とルーン画像取り込み

- 現行はRuneEditorWindowからRuneImagePreprocessor.Binarize → RuneSkeletonizer.Skeletonize → RuneStrokeExtractor.Extract → RunePathSimplifier.Simplify → AuthoringDataへ適用 → Bakeする制作支援。プレイ中のなぞり判定とは別の経路。
- 二値化はRGBの明るさだけを使用し、alphaを参照しない。透明部分のRGBによって背景を線として拾う可能性がある。透明背景を白へ合成してから閾値判定する方式が第一候補。
- 抽出は端点・分岐点を起点とする。起点のない単純な閉ループは抽出対象から漏れる。未訪問の接続を全体から拾う第二走査が必要。
- 分岐付近の短い線、隣接する分岐点、画順・方向の決定は別問題。画像だけから本来の筆順を確定せず、編集画面の結合・分割・反転・並べ替えを残す。
- AnalyzeRuneImageは同じSkeletonへExtractを2回呼んでいる。結果を1回だけ取得する形に整理可能。
- 優先順：透明背景対応 → 閉ループ対応 → 分岐部の改善。透明黒背景・白背景・円・交差・斜線・離れた複数線で抽出結果を確認する。元画像と既存RuneDataは自動で上書きしない。既存ファイルの文字コードを保って編集する。
- 「画像認識」がプレイ中のなぞり判定改善を指す場合は対象が異なるため、着手前に具体的な困り方を確認する。

## 本末尾の設定ページ

実装可能と判断するが、操作できる試作による確認は未実施。

- YasudaBookViewControllerはページをRenderTextureへ撮影して表示し、めくり用に複製したLive CanvasのGraphicRaycasterを無効化する。表示元カメラはアニメーション表示のため継続描画しているが、表示先の本から撮影元UIへ入力を転送する処理はないため、ButtonやSliderの配置だけでは操作を接続できない。
- 第一案：現在の本の座標変換に合わせて、開いている設定ページ上へ操作用uGUIを重ねる。Button・Sliderの入力はそのUIが受け持ち、設定値は独立した設定サービスへ渡す。めくり中・閉じている間はUIを隠し、ドラッグ中にページめくりが始まらないよう操作開始時から入力を占有する。
- 本の変形に厳密に沿わせる必要があれば、ページ座標へ変換した入力を撮影元UIへ転送し、変更時に表示を再撮影する方式を検討する。押下・ドラッグ・解放・キャンセルとpointer IDの管理が必要なため、まず重ねる方式で検証する。
- 末尾固定枠は所持上限・削除・入れ替えの対象外として維持する。設定画面をルーン用PageInstanceとして無理に扱わず、固定見開きで独立して起動する。
- 最小試作はLanguage切替ボタンと試験用スライダー1本。実際に扱う音量等の項目は未指定。スライダーの値変更、クリックとの区別、ページ端との競合、めくり後の入力解除を確認する。
- Languageは表示文字列の切替に使用し、内部のPageId・魔法ID・通信値は変更しない。英語化で設定への入口を塞がない。言語名は「日本語 / English」のように読める表記を残す案。
- 保存するユーザーの言語設定と、敵による一時的な英語化を分離する。解除操作で敵効果を終了し、保存設定まで勝手に書き換えない。通常の言語変更との扱いは仕様確定時に決める。

## お邪魔アクション

| 効果（提示された要件） | 解除操作 | 実装案・決めること |
| --- | --- | --- |
| ページに物が当たり皺だらけ | ピンと引っ張る | 端をつかんで外へドラッグ。二本指で両端を引くか、一方向ドラッグかは未決定。皺はまず重ね画像で表現し、本のメッシュ変形は後段。 |
| べとべとで見えない | 左右へゴシゴシ | ページ内の一定距離を超えた左右反転を加算。細かな手ぶれと同一位置の往復だけで解除されない閾値を用意。全面の回数制か、擦った場所の汚れ除去かを決める。 |
| 石化 | ページ連打 | 有効な押下・解放を1打としてひび割れを進める。押しっぱなしやフレーム数を連打に数えない。 |
| 文字が散乱 | 連打、または本を振る | 当初は連打を再利用可能。振る方式は画面内の本ドラッグか端末の加速度か未決定。文字は背景画像に焼き込まれている場合、文字ごとの素材分離が必要。 |
| 本全体が英語になる | 末尾設定で日本語へ戻す | 本全体の一時効果。設定ページへの移動と言語ボタンは操作可能に保つ。 |
| 使用済み状態 | 時間経過を待つ | 終了時刻を保持し、ページを移動してもタイマーをリセットしない。見た目、使用を止める対象、時間、重複時の延長規則は未決定。 |
| ページがバラバラ | ある程度正しい位置へ揃える | 断片をドラッグし、位置の許容範囲内で固定する。回転合わせの要否・断片数・正解表示は未決定。 |
| カピカピの黒インク | スクラッチ式に擦る | 透明化マスクへ移動区間を連続して描き、除去済み面積で完了判定。すでに消した部分を擦っても進捗を増やさない。 |

### 共通の管理と入力

- ページ種類として追加するお邪魔ページか、既存ページへ付与される状態異常かは未確定。後者を第一案とするが、入手・削除仕様に勝手に結び付けない。
- ページ単位の効果はPageIdではなくPageInstanceに紐付け、同種ページの別個体へ波及させない。英語化など本全体の効果は本側に保持する。
- 効果の状態・進捗・終了時刻と、画面上の表現を分離する。ページを離れると表示と保持中入力を終了し、戻ったら状態から復元する。解除成功だけではページを自動削除しない。
- 当初は1ページ1効果を推奨。重複付与時の置換・延長・拒否は未確定。本全体の効果との併存も明文化する。
- 入力の優先順案：選択等のモーダル → 設定UI → お邪魔解除 → ルーン・ページめくり。操作開始時に処理先を固定し、同じドラッグを複数系統へ配らない。フォーカス喪失・ページ移動・無効化で占有を解除する。
- お邪魔がルーンだけを止めるのか、めくりも止めるのかは効果ごとに定義する。特に英語化中のめくりは設定到達のため残す。
- 敵からの付与は、対象個体・効果種別・必要な時間等を受ける入口を分離する。既存ADD_PAGEを流用せず、通信メッセージ変更はチーム側仕様が決まってから扱う。

## 4枠方式の確定仕様（2026-10-28・上記の旧お邪魔案より優先）

### ユーザー合意済み
- 各PageInstance（左右の見開き）に独立した4枠を保持する。段階数と単一効果を持つ方式ではない。
- PCからの受信時に開いている見開きへ付与。ページめくり中なら予約し、めくり完了直後の見開きへ適用する。
- 1〜3番枠は右側説明ページの指定範囲内へ表示。4番枠は左のルーン領域へ大きく表示する。
- 4番枠が存在する間だけ通常のページアクションとページめくりを禁止する。解除入力は受け付ける。1〜3番枠を先に解除しても禁止は継続し、4番枠を解除すれば他の汚れが残っていても通常操作を再開する。
- お邪魔の種類に応じて1回の付与で複数枠を埋められる。各枠は独立して解除できる（例：2・3番枠の黒インクの片方だけ解除可能）。
- 若い番号の空き枠を先に埋め、不足分だけ古いお邪魔の枠から上書きする。全枠を埋める種類は全枠を置換する。古さは各枠への付与順で管理する。
- 上書き対象の解除進捗はリセットする。解除後も残ったお邪魔は詰め直さない。
- ページを離れても各枠のお邪魔種類・解除進捗を保持する。

### 推奨構成（具体的な型名・APIは未実装）
- PageInstanceに4枠の管理を保持。割当・付与順・上書き・解放・4番枠による操作制限を共通管理へ集約する。
- 各枠に独立したお邪魔の実体と解除進捗を置く。複数枠の付与元を記録する場合も、解除進捗を共有しない。
- 種類の設定データに通信種類ID、使用枠数、画像、解除パラメータを置く。派生クラスは種類ごとに増やさず、左右擦り・スクラッチ等の解除方式ごとに分ける。
- 共通入力窓口でページ座標へ変換し、押下位置で解除／ルーン／めくりの処理先を決め、解放まで入力の所有者を固定する。種類別処理へ押下・移動・解放・キャンセルを渡す。
- 状態と表示の寿命を分離。スクラッチは除去面積だけでなく除去形状も保持して復元する。
- お邪魔付与専用の通信を追加する案。種類IDと付与イベントIDを候補とする。既存ADD_PAGEの意味は変えない。
